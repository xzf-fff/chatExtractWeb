chat-demo 是什么、能做什么What is chat-demo?

它是 DeepSeek 官方开源的「API 使用 demo」，一个静态网页。我们生成的 ZIP 最终就是导入到这里——所以先搞清它能做什么、不能做什么。It is DeepSeek's open-source “API usage demo”, a static website. The ZIP we produce is imported there — so it's worth knowing what it does and doesn't do.

它是什么What it is

  • DeepSeek 官方仓库 deepseek-ai/chat-demo 的开源项目，MIT 许可，纯静态站点；An open-source project in DeepSeek's official deepseek-ai/chat-demo repo, MIT licensed, a pure static site;
  • 官方部署地址：deepseek-ai.github.io/chat-demo；official deployment: deepseek-ai.github.io/chat-demo;
  • 用途是演示 API 的对话能力，界面里的数据保存在**你当前的浏览器**里，具体行为以官方仓库为准。It demonstrates the API's chat capability, and its data lives in your current browser; the official repo is the reference for details.

为什么它和「导出数据」有关Why it matters for exports

真正的 DeepSeek 账号数据在云端，导出出来是一个 ZIP。chat-demo 提供了一个把这种 ZIP **重新装回界面里浏览**的入口：「设置 → 数据管理 → 导入历史对话」。这也是我们能验证「导出包是否合法」的最直接方式——导入成功，说明包结构和字段都对。Your real account data lives in the cloud; the export is a ZIP. chat-demo offers a way to load such a ZIP back into a UI via “Settings → Data → Import history”, which is also the most direct way to verify that a package is valid: if it imports, the structure and fields are right.

怎么导入How to import

  1. 打开官方 chat-demo；open the official chat-demo;
  2. 进入「设置 → 数据管理 → 导入历史对话」；go to “Settings → Data → Import history”;
  3. 选择你要导入的 ZIP，确认；pick the ZIP and confirm;
  4. 检查列表数量是否与包内一致、点开确认图片能显示。check that the list count matches the package and that images render.

导入是整包替换：会先清空 demo 里已有的对话与附件，再写入包内的。所以导入前请先在 demo 里「导出所有历史对话」备份一次。Import replaces everything: it clears the demo's existing conversations and attachments, then writes the package contents. Export your current history inside the demo first.

它对包的三个要求Three package rules it enforces

  1. manifest.json 必须是第一个条目（内容是 {"export_format_version":3}）；manifest.json must be the first entry (holding {"export_format_version":3});
  2. 索引里的会话 id 集合必须与包内 chat_sessions/*.json 完全相等；the index's id set must exactly equal the packaged chat_sessions/*.json;
  3. 条目顺序固定：manifest → user.json（可选）→ 会话 → 索引 → 附件。fixed order: manifest → user.json (optional) → sessions → index → attachments.

细节和原因见 导出包结构详解；报错怎么排查见 报错排查。Details in the export structure article; error handling in troubleshooting.

它不能做什么What it can't do

  • 不会影响你账号里的云端对话——导入只作用于当前浏览器；it does not touch your account's cloud conversations — the import is browser-local;
  • 不是官方 App 的替代品，也不提供账号同步；it is not a replacement for the official app and has no account sync;
  • 清理浏览器数据（或换浏览器）后，导入的对话会消失——需要长期保留就自己存好 ZIP。clearing browser data (or switching browsers) loses imported conversations — keep the ZIP if you need them long-term.

三个常见疑问Three questions

  • 导入后对话变少了？不是丢了，是包内本来就只有这些——导入是替换。Fewer conversations after import? Nothing was lost: the package only had those. Import replaces.
  • 图片显示不出来？附件没跟着打包，或 export_path 与包内路径不一致，见 图片与附件。Images missing? Attachments weren't packaged or export_path doesn't match — see images and attachments.
  • 导入失败？先对照 报错排查 的四种错误，多数是包结构问题。Import failed? Check the four errors in troubleshooting; most are package-structure issues.
