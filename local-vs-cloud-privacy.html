聊天记录导出交给谁Who gets your chat export

导出包里有你和 AI 的完整对话，很多时候还有截图。选哪种方式整理它，本质上是在选「谁有机会看到这些内容」。An export contains your full conversation history — often with screenshots. How you process it decides who gets a chance to see it.

三条常见路线Three routes

  1. 手工改 ZIP：解压、删会话、改索引、重新压缩。数据不出本机，但容易踩条目顺序、索引一致性这些坑（见 报错排查）。Edit the ZIP by hand: unzip, delete sessions, edit the index, re-zip. Data stays local, but entry order and index consistency are easy to break (see troubleshooting).
  2. 网盘 / 在线转换站：把 ZIP 上传到某个服务，由它处理再给你下载。方便，但整包对话（含截图）已经离开了你的设备。Cloud drive or online converter: upload the ZIP, let the service process it, download the result. Convenient — but the whole export, screenshots included, has left your machine.
  3. 本地浏览器工具：页面在本地读文件、在内存里处理，只有你点下载时才写盘。门槛低、不用上传。Browser-local tool: the page reads the file, processes it in memory and only writes to disk when you download. Low effort, no upload.

「本地工具」也会有网络请求“Local” still makes network requests

要区分两件事：页面加载了什么，和你的文件有没有被送出去。一个纯前端工具完全可以带着广告或统计脚本，但它不需要、也不应该把你的 ZIP 上传到任何地方——上传文件需要主动写代码（fetch / XMLHttpRequest / sendBeacon）。Separate two things: what the page loads and whether your file is sent anywhere. A front-end tool can carry ads or analytics and still never upload your ZIP — uploading requires deliberate code (fetch / XMLHttpRequest / sendBeacon).

怎么自己验证一个工具真的不上传How to verify it yourself

  1. 断网测试：打开页面后拔网线/关 WiFi，再拖入导出包。如果处理流程照常走完，说明核心逻辑确实在本地。Go offline: open the page, disconnect the network, then drop the export in. If processing still completes, the core logic is local.
  2. 看 Network 面板：F12 → Network，操作一遍，筛选 Fetch/XHR，检查有没有请求把文件内容作为请求体发出去。Watch the Network panel: F12 → Network, run through the flow, filter Fetch/XHR, and check whether any request carries file content.
  3. 搜源码：开源工具直接搜 fetch(、XMLHttpRequest、sendBeacon、FormData，看有没有把 File/Blob 发出去。Search the source: in an open-source tool, grep for fetch(, XMLHttpRequest, sendBeacon, FormData and check whether any File/Blob is sent.
  4. 看隐私政策：有没有坦白列出第三方脚本（广告、统计）以及它们能拿到什么。Read the privacy policy: does it list third-party scripts and what they can access?

本站的边界，写清楚Our own boundaries

  • 两个工具：文件只在浏览器内存里处理，不上传；工具页不加载任何广告或统计脚本。The two tools process files in browser memory only; the tool pages load no ads or analytics.
  • 内容页（首页、指南、文章、报错、隐私）有 Google AdSense，会向 Google 请求广告并可能使用 Cookie——但它接触不到你选择的文件。Content pages carry Google AdSense, which requests ads from Google and may use cookies — but has no access to the files you select.
  • 源码公开，上面四条验证方法都可以自己跑。The source is public, so all four checks above can be run yourself.

几条实用建议Practical tips

  • 含敏感信息的对话，优先用本地方式处理，处理完把中间产物删掉。For sensitive conversations, prefer local processing and delete intermediate files afterwards.
  • 分享前先裁剪（只保留需要的会话），并确认包里没有 user.json。Trim before sharing (keep only what's needed) and make sure user.json is not inside.
  • 必须走网盘时，先加密压缩再上传，链接设有效期。If you must use a cloud drive, encrypt the archive first and set an expiry on the link.
  • 截图类附件最容易泄露信息，逐张看过再决定要不要带出。Screenshots leak the most; review them one by one before exporting.
