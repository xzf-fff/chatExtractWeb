导出包太大怎么办My export is huge

几百组对话的导出动辄几十 MB，绝大多数体积来自图片，而不是文字。想瘦身，得先知道花在哪。A few hundred conversations easily reach tens of MB, and the bulk is images rather than text. To shrink it you first need to know where the weight is.

体积花在哪Where the size goes

一个导出包里通常有三类内容：An export holds three kinds of content:

  • 会话 JSON：纯文本，几百组对话也就几 MB；压缩后更小。Session JSON: plain text; a few hundred conversations amount to a few MB, less after compression.
  • 附件（图片）：通常是绝对大头。截图按原分辨率保存，单张几百 KB 到 1 MB 很常见。Attachments (images): usually the dominant cost. Screenshots are stored at full resolution; 0.3–1 MB each is normal.
  • 索引与 manifest：可忽略，几十 KB。Index and manifest: negligible, tens of KB.

经验值：带图的会话往往只占会话总数的个位数百分比，却能占掉 80% 以上的体积。Rule of thumb: image-bearing conversations are often a single-digit percentage of the total, yet account for over 80% of the bytes.

最有效的三招Three effective moves

  1. 只勾选需要的会话——这是唯一真正有效的大杠杆。导入 demo 本来就是「整包替换」，你不需要的对话留着只会占体积。Select only what you need — the only large lever that exists. Import replaces everything anyway, so unneeded conversations just add weight.
  2. 先看清哪些会话带图：用「带图片」筛选，去掉不重要的带图会话，往往一次就能砍掉一半以上。See which conversations carry images: filter by “images” and drop the unimportant ones — often halves the package in one pass.
  3. 不要包含账号信息：user.json 很小，但含账号标识，默认不要带出去（勾选项默认关闭）。Leave account info out: user.json is small but identifies your account; it is off by default.

会让你白忙或把包弄坏的做法What wastes effort or breaks the package

  • 用系统压缩工具再压一次：JPEG/PNG 已经压缩过，二次压缩几乎不省体积，却会打乱 ZIP 条目顺序 → 「无法识别该文件」。Re-zipping with the OS archiver: images are already compressed, so you save almost nothing while reordering ZIP entries → “unrecognized file”.
  • 批量重压缩图片：会改变文件字节，某些情况下与包内记录的尺寸/大小不一致，徒增风险；想省空间不如直接不选那些会话。Batch re-compressing images: changes bytes and can disagree with the recorded dimensions/size, adding risk for little gain — dropping those conversations is simpler.
  • 手工删附件文件：正文里的 export_path 还指着它，导入后图片全裂（见 附件数据已损坏）。Deleting attachment files by hand: export_path still points at them, so every image breaks (see corrupt attachment).

多大算大How big is too big

几十 MB 完全正常，浏览器处理起来没有压力。真正需要留意的是**几百 MB 以上**：所有处理都在内存里完成，超大包可能让标签页卡顿甚至崩溃。如果只是想看几组对话，没必要把整包导入。Tens of MB is normal and the browser handles it fine. The concern starts at hundreds of MB: everything is processed in memory, and very large packages can make the tab sluggish or crash. If you only need a few conversations, don't import the whole archive.

具体步骤Steps

  1. 打开 子集提取器，载入全量导出；open the subset extractor and load the full export;
  2. 用「带图片」筛选看一眼哪些会话最占体积；filter by “images” to see which conversations are heaviest;
  3. 按标题搜索出真正需要的会话并勾选，其余清空；search for the ones you actually need, tick them, clear the rest;
  4. 底部会实时显示「原始体积」，确认在可接受范围；the footer shows the running size — check it is acceptable;
  5. 生成 ZIP 并自检通过后下载。generate the ZIP, let the self-check pass, download.
