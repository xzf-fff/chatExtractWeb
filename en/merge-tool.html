合并规则与导入验证

如何对齐：按 会话 id 分组，按 消息 id 对齐。只在某一版存在的消息自动保留；同一消息 id 内容不同即为「冲突」，由你逐条选择。id 错位会自动纠正：DeepSeek 每次导出可能重排消息 id（中间删过消息，后面的 id 整体前移），此时工具改用「角色 + 正文」的序列对齐，把两份导出的 id 归一化后再比较，并弹出提示。

内容相同判定：比较 role、parent_id 与 fragments（正文/思考/工具结果）。只差元数据不算冲突：时间戳、token 统计、宽高/文件大小、file_id，CONTENT_RISK/TIP 这类系统安全提示的多一条少一条，以及 content 为空的空片段（例如一边多一个空 REQUEST），都会被忽略。导出时仍取你选中那一版的完整字段，数据不会丢。

分支：会话本身是消息树，current_message_id 决定 demo 打开时显示哪条分支。合并后可在右栏「当前分支」里选任意叶子节点，未被选中的分支仍然保留在消息里。

示例：列表空白处的「载入内置示例」会生成两份合成导出（A 旧版 / B 新版），含一条冲突消息、一个新分支和各自的附件。可以直接走完「选冲突 → 选 head → 导出 → 自检」的完整流程，不需要任何真实数据。

导出：未打开过的会话按默认规则（每条冲突取较新版本）合并；已打开并手动选过的以你的选择为准。索引按合并结果重算 message_count，附件取各版本的并集。

导入会覆盖 demo 本地全部对话；下载的 ZIP 含完整对话，请谨慎分享。

推荐 Chrome / Edge 最新版。载入失败时请解压后拖入文件夹/ZIP。
