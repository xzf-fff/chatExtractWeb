Images and attachments in an export

Text lives in JSON, images live as separate files, and a single string (export_path) connects them — which is exactly why images often break after import.

On this page

Where files live

Each conversation gets one folder, named by convention:

chat_sessions/
├── <session-id>.json          # 会话正文
└── <session-id>_files/        # 这个会话的所有附件
    ├── <fileId>_image.png
    └── <fileId>_image.png

The prefix is the file id (a UUID) and the suffix is the original name. Images are usually called image.png, so a conversation can contain many same-named files distinguished only by the id prefix.

What export_path is

Attachments inside a message are not binary data but a FILE fragment listing metadata:

{"type":"FILE","files":[
  {"id":"d4108600-…","file_name":"image.png",
   "export_path":"chat_sessions/<session-id>_files/d4108600-…_image.png",
   "file_size":142341,"is_image":true,"width":1400,"height":985}
]}

export_path is the relative path inside the archive and must match the real file location verbatim. It is the only link between a message and its file; one wrong character and the image cannot be loaded.

Why images break

  • Only the JSON was copied: packing chat_sessions/*.json without _files/ keeps text but leaves every image blank.
  • Paths were rewritten: moving or renaming files without updating export_path.
  • Case mismatch: Windows ignores case, the importer does not.
  • Non-ASCII names: Chinese filenames make chat-demo reject the whole package — its ZIP parser refuses non-ASCII entry names.
  • Merge took only one side: attachments live in per-export folders, so packing one side loses the other's images.

Four packaging rules

  1. Pack attachments with their conversation, keeping chat_sessions/<id>_files/<name>;
  2. never rename, move or recompress them;
  3. entry names must be ASCII only;
  4. when merging exports, union attachments by path (prefer the newer version on the same path).

The subset extractor checks that every export_path starts with that conversation's _files/, that the file exists and that the name is ASCII; the version merger unions attachment folders across versions. Any failure blocks the export and names the conversation.

Size in practice

Images dominate package size: a several-hundred-conversation export may have only a handful of image-bearing chats, yet the images alone can run to tens of MB at full resolution. The tool shows the running size while you select.

Before sharing

Most exported images are screenshots that may contain phone numbers, addresses or account screens. The ZIP carries them verbatim, so review them before sharing to group chats or public drives — or select only the conversations you need.
