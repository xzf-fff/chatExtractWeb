chat-demo import troubleshooting

The four most common import failures: symptom, cause, then the fix.

On this page
Unrecognized file Incomplete content Broken branch Corrupt attachment Why hand-editing fails Fix it with the tools

“Unrecognized file”

Symptom: the error appears right after picking the ZIP, before any progress.

Cause: manifest.json is not the first entry, or export_format_version: 3 is missing. The demo parses the archive as a stream and reads the manifest first; re-zipping with the OS “Compress” command reorders entries.

Fix: export with these tools (manifest is always written first); never re-zip with the OS archiver.

“Incomplete content”

Symptom: the import stops midway and the conversation list stays unchanged.

Cause: the ids in chat_session_index.json do not exactly match the packaged chat_sessions/*.json; or the index sits before the session files, so later entries get treated as attachments.

Fix: when keeping a subset, prune the index too; the order must be manifest → user.json → sessions → index → attachments.

“Message branch is broken”

Symptom: import succeeds, but opening a conversation fails or shows nothing.

Cause: current_message_id or some message's parent_id points at a message that does not exist — typical when splicing two exports together or merging without recomputing ids and parents.

Fix: re-merge with the version merger: it aligns both exports by content, recomputes message ids and parent links, and points the current branch at an existing leaf.

“Attachment data is corrupt”

Symptom: text renders but every image is broken.

Cause: the FILE fragment's export_path does not match the packaged path, or the file is missing; non-ASCII entry names (e.g. Chinese filenames) are also rejected.

Fix: copy attachments verbatim to chat_sessions/<session-id>_files/<filename> — no renaming, no moving.

Why hand-editing a ZIP breaks

The demo's importer is stricter than most tools; four hard constraints stack up:

  1. Entry order: manifest first, attachments after the index.
  2. Matching id sets: index entries and session files must correspond one to one.
  3. ZIP limits: Store/Deflate only; no ZIP64, data descriptor, encryption, or non-ASCII entry names.
  4. Field checks: timestamp format, role/status enums, and self-consistent parent_id/current_message_id.

Fix it in one go

Both tools validate all four rules before exporting, block on errors with the offending conversation named, then re-parse the produced ZIP (first entry, order, CRC, index consistency) before offering the download — so these four errors practically disappear.
