# DeepSeek 历史对话子集提取

从 DeepSeek 导出的 `deepseek_data-YYYY-MM-DD/` 目录（几百组对话）中按**标题**挑出指定对话，打包成一个可直接导入 `chat-demo` 的 ZIP。原始导出数据只读，不会被修改。

**在线使用：<https://fastaibook.tech>**（英文：<https://fastaibook.tech/en/>）· 纯前端，数据不上传，也可下载后离线打开。

![ChatExtract](assets/og.png)

两个工具，产物格式一致：

| 工具 | 适用场景 |
| --- | --- |
| `subset-tool.html`（网页） | 可视化搜索、预览对话内容与图片、勾选导出、页内自检 |
| `merge-tool.html`（网页） | 合并两次不同日期的导出：按消息 id 对齐、逐条解决冲突、重算索引后导出 |

两个网页工具的顶部都有「子集提取 / 版本合并」切换按钮，打开任意一个都能切到另一个，不用记文件名。

## 为什么不能直接导入原始数据

`chat-demo-v0.1.1` 的「导入历史对话」会**覆盖本地全部对话**，且导入时强校验：

- `manifest.json` 必须是 ZIP 的第一个条目；
- `chat_session_index.json` 里的会话 id 集合必须与包内 `chat_sessions/*.json` 的 id 集合**完全相等**。

所以只想保留几组对话时，必须同时裁剪会话文件与索引。本仓库用网页工具重新打包：可视化检索、可视化预览，导出前按 demo 规则校验。

## 方式一：网页工具 `subset-tool.html`

单文件、零依赖、可离线，双击即可用（也可用任意静态服务器托管）。

1. **打开**：双击 `subset-tool.html`，或访问 `http://localhost:端口/subset-tool.html`。
2. **载入数据**：把 `deepseek_data-YYYY-MM-DD` 文件夹（或 DeepSeek 导出的 ZIP）拖进页面，或点右上角「选择文件夹 / 选择 ZIP」。载入后顶部显示数据源名称与「N 组对话 · M 张图片」。
3. **检索与多选**：搜索框按标题过滤（忽略大小写/全半角/多余空格，快捷键 `/`），可按「最近更新 / 消息数 / 标题」排序，按「带图片 / 重名 / 已选」筛选；支持「全选当前 / 反选 / 清空」。
4. **预览**：点标题打开右侧预览，用户/助手气泡、思考过程折叠、搜索与链接卡片、图片缩略图（可点开大图），面板内可直接「加入导出 / 移出导出」。
5. **生成与自检**：底部实时显示校验状态（错误会阻止导出）与已选体积；点「生成 ZIP」后按 `manifest → 会话 → 索引 → 附件` 的合法顺序打包，并在浏览器内复解析自检（顺序 / CRC / 索引一致性）通过后才提供下载。
6. **验证**：点「打开 chat-demo 验证」→ demo 中进入 **设置 → 数据管理 → 导入历史对话** → 选择刚下载的 ZIP。导入会**覆盖本地全部对话**，需要保留时请先备份。

### 导出选项：包含账号信息（默认关闭）

侧栏「导出选项」中的 **包含账号信息** 开关控制是否把 `user.json` 打进 ZIP：

- **默认关闭**：`user.json` 含 `user_id`、脱敏手机号、微信昵称与头像地址，分享 ZIP 时会连带泄露；不开开关即不写入。
- **手动开启**：仅在你需要保留账号信息（例如自用备份）时打开，页面会提示风险，同时已选体积会包含该文件。
- 关闭时生成的包依然能正常导入 demo（`user.json` 对导入是可选项）。

> ⚠️ **下载包请谨慎分享**：ZIP 内含完整对话正文与图片（可能包含聊天截图等敏感内容），不要上传到公共网盘、群聊或公开仓库。

浏览器推荐 **Chrome / Edge 最新版**（`CompressionStream` / `DecompressionStream` 支持最好）。Safari 不支持「选择文件夹」，Firefox 的目录拖拽支持也有限；若载入失败或浏览器缺少解压能力，请**解压后拖入文件夹/ZIP** 再试。

## 生成物内容

```
chat_subset.zip
├── manifest.json               # {"export_format_version":3}，必须第一个条目
├── user.json                   # 可选：放在会话之前；默认不导出，需要时在侧栏勾选
├── chat_sessions/<id>.json      # 会话正文，字节原样复制
├── chat_session_index.json     # 仅保留所选会话的条目；必须排在所有会话之后
└── chat_sessions/<id>_files/    # 图片附件；必须排在索引之后
```

**条目顺序是有约束的**：demo 按条目流顺序解析状态机，索引一旦排在会话前面，后续会话文件会被误判为附件而报「文件内容不完整」（UI 只显示笼统的“文件导入失败”）。因此顺序必须是 `manifest → user.json → 会话 JSON → 索引 → 附件`，与官方导出完全一致。

打包前会校验：会话正文存在且 id 一致、附件 `export_path` 合法且文件存在、无路径穿越，并按 demo 的规则检查时间格式、`message_count`、`status`/`role` 枚举、`current_message_id` 与消息父子链（不满足会导致 demo 报“分支损坏”）。打包后重新打开 ZIP 自检：首条目为 `manifest.json`、条目顺序合规、索引与会话文件 id 集合一致、无重复或非法条目名。任一步失败都会中止，不会产出半成品。

## 导入 demo

1. 打开官方 chat-demo：<https://deepseek-ai.github.io/chat-demo/>；
2. 进入 **设置 → 数据管理 → 导入历史对话**；
3. 选择 `output/` 下生成的 ZIP，确认导入。

注意：导入会覆盖本地已有的全部对话与附件，导入前如有需要请先在 demo 中「导出所有历史对话」备份。

## 合并两个日期的导出：`merge-tool.html`

同一次对话如果在两个日期各导出过一次，两份数据里的**会话 id 相同、消息 id 相同**，但正文可能被编辑过，也可能多出新消息或新分支。本工具把多份导出当作同一批对话的不同「版本」合并，产物同样是可直接导入 `chat-demo-v0.1.1` 的 ZIP。单文件、零依赖、可离线。

1. **载入版本源**：点右上「添加文件夹 / 添加 ZIP」，或把导出包拖进页面，依次标记为 A、B、C…（至少两个，多份也可以）。每份数据的根目录需含 `chat_session_index.json` 与 `chat_sessions/`。**没有现成数据时**，点列表空白处的「载入内置示例」，会得到两份合成的 A/B 导出并自动打开示例会话。
2. **按会话 id 分组**：只有 id 相同才会被视为同一对话的不同版本；列表显示各组在各版本里的消息数与更新时间，可按「全部 / 有差异」筛选（「有差异」只列**两个版本都有、但内容不同**的会话，只在某一边出现的会话归到「全部」里），支持「全选当前 / 反选 / 清空」。
   **消息 id 会被重排**：DeepSeek 每次导出会重新编排会话内的消息 id——中间删过消息后，后面的 id 整体前移（实测 11-18 与 11-20 两份导出，同一条「2022地市」在 A 里是 `#383`、在 B 里是 `#373`，整段错位 10）。工具检测到这种错位时，会改用「角色 + 正文」做序列对齐（LCS），把两份导出的 id 归一化到同一套编号后再比较，并弹出一次提示；id 本来就一致时不会触发重排。同一会话实测：不纠正时 210 条「冲突」，纠正后 24 条，再滤掉空片段后 **0 条**（该会话两版正文其实一条没改）。
3. **逐条解决冲突**：点会话在右栏对比。同一消息 id 的 `role`、`parent_id`、`fragments` 一致即视为相同；**只差元数据不算冲突**——时间戳（含联网搜索结果的 `published_at`）、token 统计、宽高/文件大小、`file_id`、`CONTENT_RISK`/`TIP` 系统提示的多一条少一条，以及 **content 为空的空片段**（实测同一会话 24 条残留冲突全是“B 多一个空 `REQUEST`”，滤掉后为 0）。真正内容不同的才并排展示两版正文，由你选择保留哪一版，也可「全部取较新 / 全部取较旧」。只在某一版存在的消息无需选择，自动保留。
4. **选定当前分支**：会话是消息树，`current_message_id` 决定 demo 打开时显示哪条分支。默认取最新版本的 head；若该消息在合并结果里不存在，则退回首个叶子节点。可在右栏下拉里改选任意叶子，未选中的分支仍完整保留在消息里。
5. **导出**：底部点「合并并导出 ZIP」。导出前做与 `subset-tool` 相同的 demo 兼容校验，通过后按 `manifest → user.json → 会话 → 索引 → 附件` 顺序打包，并复解析自检（首条目 / 顺序 / CRC / 索引与会话数量一致），任一步失败都不会产出半成品。

### 合并与重算规则

| 项目 | 规则 |
| --- | --- |
| 分组 | 按会话 `id`；同一 id 的多份文件视为不同版本 |
| 消息对齐 | 按消息 `id`；两份导出 id 被重排过时，先用「角色 + 正文」序列对齐（LCS）归一化 id，再按 id 对齐；同 id 且内容相同 → 复用较新版本的完整字段 |
| 冲突 | 同 id 且正文/思考/工具结果不同；忽略时间戳、token 统计、宽高/文件大小、`file_id`、`CONTENT_RISK`/`TIP` 系统提示的差异，以及 **content 为空的空片段**（例如一边多一个空 `REQUEST`）；未手动选择的冲突默认取较新版本 |
| 单侧消息 | 只在部分版本出现的消息自动保留 |
| 分支 | 所有消息（含未选中分支）写入结果，仅 `current_message_id` 指向所选叶子 |
| 标题 | 取各版本中存在的最新 `title` |
| 时间 | 会话 `inserted_at` 取各版本最早，`updated_at` 取最晚 |
| 索引 | 按合并结果重算 `message_count`，`pinned` 统一为 `false` |
| 附件 | 各版本 `chat_sessions/<id>_files/` 取并集，同路径优先较新版本 |
| 账号信息 | 与 `subset-tool` 一样默认不写 `user.json`，需要时手动勾选「包含账号信息」 |

**勾选规则**：首次载入的版本源会全选它的会话；之后新增版本源时，只有同时存在于各版本的会话会自动勾选，**仅单源存在的会话默认不勾选**，避免误把只在某一版出现的对话一起导出。用「全选当前 / 反选 / 清空」批量调整，导出只包含勾选的会话。改动勾选、冲突选择或当前分支后，之前生成的包会立即失效，需要重新导出。

### 验证

- 页面底部「自检」：用已选的前两组会话在内存里生成样本包并复解析，显示合并后消息数、head、demo 兼容校验与结构自检结论。
- 正式导出后再导入 demo（步骤同上）。导入会覆盖本地全部对话，导入前先备份。
- 合并与导出已用**合成双版本数据**（同 id 冲突、单侧消息、双分支、同名与单侧附件）和**真实导出目录**（含图片的会话，单源）验证：冲突识别、手动选择覆盖、head 选择、索引重算、附件并集、条目顺序与自检（含首条目错误、CRC 不符的负向用例）均通过。
- 页面暴露 `window.__MERGE__`（`diffVersions` / `buildZip` / `parseZip` / `selfCheck` / `checkSession` / `crc32` / `isDemoTs` 等）供本地脚本做自动化验证；其中 `state` / `registerSource` / `mergedSession` / `validateSelection` / `loadSample` / `generate` 会改动内部状态，仅供测试调用。

## 示例：两个工具怎么配合

### 示例一：从全量导出里挑 3 组对话

打开 `subset-tool.html`，在搜索框输入标题关键词（例如 `季度复盘`、`部署笔记`），勾选目标对话（同名标题会同时列出多条，按更新时间区分）；底部确认校验状态为绿色后，点「生成 ZIP」→「下载」。

### 示例二：合并两次导出的同一组对话

以 `merge-tool.html` 的「载入内置示例」为例（A = 2026-11-01、B = 2026-11-15）：

1. 载入后自动打开主会话，右侧可以看到每一行消息的归属与冲突：
   - 消息 `#1`、`#2` 两版正文一致，仅时间戳不同 → 自动判为相同，复用较新版本；
   - 消息 `#3` 的正文被改过 → 冲突，默认取 B，点 A 侧可改回旧版；
   - 消息 `#4` 只在 A，`#5`、`#6`、`#7` 只在 B → 自动保留，列在「自动合并项」；
   - A 的 `current_message_id` 是 `#4`，B 是 `#5`；右栏「当前分支」可切换，`#6 → #7` 是另一条分支，仍会写入结果；
   - 附件 A 有 `a-old.png`、B 有 `b-new.png`，导出时取并集。
2. 底部状态显示「可以合并导出」后，点「合并并导出 ZIP」，按钮变成「下载 ZIP · …」再点一次即可下载。
3. 打开官方 chat-demo（<https://deepseek-ai.github.io/chat-demo/>）→ 设置 → 数据管理 → 导入历史对话，选择刚下载的 ZIP。

示例导出包里会有 2 组会话：主会话合并后 `message_count` 为 7（两版的并集），`chat_session_index.json` 的 `updated_at` 取 B 的较晚时间，附件目录同时包含 `a-old.png` 与 `b-new.png`。

## 隐私与分享提醒

- 对话数据不上传：解析、合并与打包都在浏览器内存中完成，只在你点「下载」时写本地文件。
- 首页、指南、报错排查、隐私政策这四个内容页含 Google AdSense 广告脚本，会向 Google 请求广告并可能使用 Cookie，但接触不到你选择的文件内容；**两个工具页不加载广告脚本**。
- 生成的 ZIP 含完整对话正文与图片（图片多为聊天截图，可能含个人信息），**请谨慎分享或上传**。
- 两个网页工具默认不导出 `user.json`（账号信息），需要时再手动开启开关。
- 预览中的链接只允许 `http(s):`，`javascript:` / `data:` 等伪协议会显示为带删除线的不可点文本（对话数据里的 URL 不可信）。
